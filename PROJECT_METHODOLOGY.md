# ABC Bank NIST Assessment – Project Methodology

## How I approached the assessment

I treated ABC Bank as a small U.S. financial institution with customer-facing applications, internal systems, payment services, endpoints, network infrastructure, security tooling and recovery capabilities.

The basic question throughout the assessment was: **what could go wrong, how serious would it be, what control should reduce the risk, and what evidence would prove that the control is actually working?**

### Assessment lifecycle

**Identify → Analyze → Assess → Treat → Implement → Test → Determine Residual Risk → Report → Monitor → Reassess**

### 1. Scope
The scope covers critical banking applications, customer information, identity infrastructure, employee endpoints, network security, monitoring, backup/recovery, ATMs, payment processing, vendors and physical infrastructure.

### 2. Asset identification
Each asset receives an owner, business criticality and data classification. Ownership is important because a risk cannot be effectively managed if nobody is accountable for it.

### 3. Risk assessment
Likelihood and impact are considered separately. Inherent risk represents the exposure before the proposed treatment. Residual risk represents the expected exposure after the improvement is implemented and operating.

### 4. NIST CSF mapping
Risks and controls are mapped to NIST CSF 2.0 Functions and Categories so that technical issues can be connected to governance, protection, detection, response and recovery activities.

### 5. Control testing
Testing is documented like an internal security assessment: define the population or sample, identify expected evidence, record what was observed, determine effectiveness, and document the action required when the control is not fully effective.

### 6. Remediation
Every significant finding has an accountable owner, target timeframe, priority and status. A finding should only be closed after supporting evidence is reviewed and, where appropriate, the control is retested.

## Portfolio disclaimer

ABC Bank is fictional. The assets, risks, evidence samples, test results and findings are simulated for cybersecurity portfolio and interview demonstration purposes. No real bank data, customer information, credentials or confidential material was used.
